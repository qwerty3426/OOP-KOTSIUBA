# IndependentWork19

## Варіант 5 — Система доступу до даних

## Опис проєкту
Цей проєкт реалізує систему доступу до даних з використанням патернів:
- Factory Method
- Singleton

Мета роботи — продемонструвати принципи гнучкої архітектури, де клієнтський код залежить від абстракцій, а не від конкретних реалізацій.

---

## Реалізована функціональність

### 1. Інтерфейс
- `IDataAccess` — визначає метод `GetData()` для отримання даних.

### 2. Реалізації інтерфейсу
- `SqlDataAccess` — імітація роботи з SQL базою даних
- `NoSqlDataAccess` — імітація роботи з NoSQL базою
- `XmlDataAccess` — імітація роботи з XML-файлом

---

### 3. Factory Method
- Абстрактний клас `DataAccessFactory`
  - визначає метод створення об'єкта `Create()`
  - містить загальну логіку `GetData()`

- Конкретні фабрики:
  - `SqlFactory`
  - `NoSqlFactory`
  - `XmlFactory`

Кожна фабрика створює свій тип об'єкта доступу до даних.

---

### 4. Singleton
- Клас `DataManager` реалізовано як Singleton
- Забезпечує єдиний глобальний доступ до системи
- Дозволяє змінювати фабрику під час виконання

Методи:
- `SetFactory(DataAccessFactory factory)` — встановлення поточної фабрики
- `GetData()` — виклик логіки отримання даних

---

## 5. Демонстрація в Program.cs

У програмі:
1. Отримується єдиний екземпляр `DataManager`
2. Встановлюється `SqlFactory` і виконується отримання даних
3. Змінюється фабрика на `NoSqlFactory`
4. Змінюється фабрика на `XmlFactory`
5. Кожен раз викликається `GetData()`

---

## Висновок
У роботі було реалізовано:
- Factory Method для створення об'єктів доступу до даних
- Singleton для контролю єдиного менеджера системи
- Слабке зв’язування між компонентами
- Можливість заміни реалізацій без змін клієнтського коду

Це забезпечує гнучкість, масштабованість та відповідність принципу DIP.
